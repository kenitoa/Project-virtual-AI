독립 오디오는 실제 CLI 명령으로 검사했다. 통합 타이밍 검사는 기존 Application/클라이언트/플레이어를 호출하는 Git 제외 관측 스크립트로 수행했다. `stop()`과 `shutdown()` 호출 결과를 콘솔 명령 파싱까지 전부 검증한 것으로 확대하지 않는다. 플레이어 호출 진행 상태 역시 실제 귀에 들리는 재생 시점과 동일하다고 단정하지 않는다.

TTS에서 확인한 것은 **Python HTTP 요청 취소**와 **취소 응답의 재생 방지**다. 서버 내부 GPU 합성 중단은 확인하지 않았으며 서버 중단 API를 추가하지 않았다. 서버가 남은 합성을 마칠 수 있으므로 다음 요청 지연도 구분한다.

관측 스크립트·결과 JSON·서버 로그는 Git 제외 `.local/readiness/`에 보관했다. 로그와 생성 음성은 커밋하지 않는다. 기존 음성 모듈에서 수정할 결함은 이번 관측에서 발견하지 않았다.

## 다음 직접 청취 순서

운영자가 들을 수 있는 시간에 실행한다. [백엔드](backends.md)의 고정 옵션으로 외부 서버를 준비하고 [자산](assets.md)의 로컬 검증 범위를 유지한다. 현재 장치를 조회한 뒤 로컬 설정과 맞는지 확인한다. 테스트 중 볼륨과 장치를 임의로 바꾸지 않는다.

```powershell
# readiness 루트
python -m uv run --locked python -m virtual_ai.audio --list-devices

# 이번 저장 파일이 있는 경우 그대로 독립 청취
python -m uv run --locked python -m virtual_ai.audio generated_audio/acceptance-01.wav --config configs/app.yaml --interactive

# LLM까지 연결한 실제 콘솔 검증
python -m uv run --locked python -m virtual_ai --config configs/app.yaml --backend koboldcpp
```

WAV가 없거나 재합성이 필요하면 기존 파일을 덮어쓰지 않는 새 이름으로 아래 명령을 실행한다. 고정 문장은 “안녕하세요. 음성 합성 테스트입니다.”다.

```powershell
python -m uv run --locked python -m virtual_ai.tts --config configs/app.yaml --output generated_audio/acceptance-02.wav
```

1. 고정 문장을 끝까지 듣고 무음·잘림·잡음 여부를 기록한다.
2. 독립 재생 중 `/stop`을 입력하고 무음을 확인한다. `/play generated_audio/acceptance-01.wav`로 다음 재생을 확인한다.
3. 독립 재생 중 `/quit`을 입력한 후 같은 CLI를 재실행한다. 소리가 멈췄고 같은 장치에서 다시 들리는지 확인한다.
4. 대화 CLI에서 일반 질문을 하고 화면 답변과 소리를 비교한다.
5. 긴 답변을 요청해 LLM 생성 중 `/stop`한다. 취소된 텍스트·음성이 뒤늦게 나오지 않는지 확인하고 다음 질문을 한다.
6. 화면 답변이 표시되고 TTS가 합성 중인 시점에 `/stop`한다. 해당 음성이 늦게 나오지 않는지 기다린 후 다음 질문을 한다. 합성 중이었는지 확인할 수 없으면 미확인으로 남긴다.
7. 실제 음성이 들리는 도중 `/stop`한다. 즉시 무음과 다음 질문의 정상 음성을 확인한다.
8. 실제 음성이 들리는 도중 `/quit`한다. 무음·프로세스 종료 후 재실행하여 다음 답변을 듣는다.

서버 중단 비활성화 또는 정리 불명으로 생성이 차단되면 강제로 우회하지 않는다. 서버의 idle=1/queue=0을 확인하고 앱을 재시작한다. 상태를 확인할 수 없으면 운영자가 해당 서버를 정리·재시작한 뒤 다시 검증한다.
