# v1.0 완료 기준과 진행 순서

> 2026-09-24 구현 통합: 별도 `Project-virtual-AI-readiness` worktree의 구현 117개 파일을 현재 IDE 작업 폴더에 반영했다. 아래의 초기 출발점 기록은 당시 상태다. 현재 구현 위치와 추가 도구는 [구현 점검](implementation-audit.md)을 따른다. 실제 장치·방송 검증과 릴리스 승인은 여전히 대기다.

기준일: 2026-09-23. 이 문서는 v1.0의 범위와 완료 판정 기준이다. 아래 항목은 요구사항이며 구현·검증 완료를 뜻하지 않는다. 이전의 초기 개발 순서와 범위 설명이 다르면 이 문서를 우선한다.

## 프로젝트 종료 기준

| 구분 | 완료 결과 |
| --- | --- |
| 기본 방송 | YouTube 채팅을 선택적으로 받아 한국어 답변을 생성하고 음성으로 출력한다. 채팅 수신을 끈 상태에서도 기본 대화가 가능하다. |
| 캐릭터 출력 | 음성에 맞춰 입이 움직이고 허용된 표정이 적용되며, OBS에 화면·음성·자막이 함께 들어간다. |
| 운영 제어 | 운영자가 즉시 중단·일시 정지·음소거·재개할 수 있다. 시청자와 모델은 운영 명령을 실행할 수 없다. |
| 기억·마이크 | 허용된 정보의 저장·조회·삭제가 가능하고, 마이크 입력을 STT로 변환할 수 있다. 두 기능은 각각 끌 수 있다. |
| 장애 대응 | 외부 서버·인증·오디오·파일 오류가 발생해도 문서에 정한 방식으로 중단하거나 기능을 축소한다. |
| 배포 | 다른 개발자가 문서만으로 설치·실행·검증하고 이전 버전으로 복구할 수 있다. |

여섯 범주의 검증과 아래 배포 단계까지 모두 통과해야 프로젝트 v1.0을 완료로 판정한다. 선택 기능도 구현과 켜기·끄기 검증은 필수이며, 매 방송에서 활성화할 필요는 없다.

## 순서와 단계별 통과 조건

선행 검증이 미완료이면 이후 코드가 존재해도 해당 순서를 통과한 것으로 처리하지 않는다. 기존 구현과 문서를 재사용하며, 단계마다 필요한 최소 변경만 한다.

| 순서 | 작업 | 통과 조건과 남길 증거 |
| --- | --- | --- |
| 1 | 기준 버전 고정 | 기준 커밋 SHA, 브랜치·PR 의존 관계, 외부 엔진·모델·환경 버전과 설정을 기록한다. 잠금 의존성 설치, mock 실행, pytest·Ruff 검사를 통과하고 복구할 기준 커밋을 지정한다. |
| 2 | 실제 음성 검증 | 고정 문장과 실제 LLM 답변을 스피커·헤드폰으로 직접 듣는다. 발음·잡음·잘림·중복 재생, 합성·재생 중 중단, 중단 후 무음·늦은 재생 방지, 다음 질문, 종료 후 재실행을 확인한다. [음성 파이프라인](voice-pipeline.md), [오디오](audio.md)에 결과를 기록한다. |
| 3 | VTS·립싱크·OBS 검증 | 최초 인증·재연결, 운영자가 허용한 표정 매핑, 재생에 맞춘 입 움직임과 중지 시 입 닫힘을 실제 모델로 확인한다. OBS 로컬 녹화에서 화면·음성·자막 동기와 오디오 중복 캡처 방지를 확인한다. [VTS](vts.md), [립싱크](lipsync.md), [OBS](obs-local-recording.md)를 따른다. |
| 4 | 기존 브랜치 통합 | 당시 원격 PR 상태와 의존 관계를 확인하고 선행 검증을 통과한 브랜치를 순서대로 통합한다. 충돌 해결 후 통합 커밋에서 공통 검증과 영향받은 실제 동작을 재확인한다. |
| 5 | 운영 제어·시작 점검 | 중단·일시 정지·음소거·재개의 상태 전이와 대기열·생성·재생 처리 규칙을 문서화하고 검증한다. 시청자·모델 입력은 제어 권한을 얻지 못한다. 시작 시 활성 기능의 설정·서버·인증·장치·파일 경로를 점검하고 실패 시 동작을 명시한다. |
| 6 | 캐릭터·출력 품질 | 캐릭터 설정에 맞는 한국어 답변, 일반 답변 1~3문장, 내부 태그·역할 구분·코드 낭독 방지를 대표 입력으로 확인한다. 텍스트·음성·표정 결과를 함께 검토한다. |
| 7 | YouTube 인증·수신·메시지 선택 | 실제 인증과 채팅 수신, 수신 비활성화, 인증 만료·실패 처리를 확인한다. 중복·오래된 메시지 제외, 대기열 상한과 초과 정책, 선택 규칙을 검증한다. 채팅 속 운영 명령은 데이터로만 취급한다. [채팅 문서](youtube-chat.md)에 기록한다. |
| 8 | SQLite 기억 | 저장 허용 대상·보관 기간·삭제 정책을 먼저 확정한다. 플랫폼·사용자별 저장·조회·삭제와 재시작 후 상태를 확인한다. 비활성화 시 영속 기억을 읽거나 쓰지 않고 기본 대화가 유지되는지 검증한다. |
| 9 | 마이크 STT | 장치 선택, 음성 입력→텍스트→기존 대화 흐름을 검증한다. 비활성화·장치 오류·인식 실패와 AI 출력음 재입력 방지 동작을 확인한다. STT 텍스트도 운영 명령 권한을 얻지 못한다. |
| 10 | 성능·장애·장시간 시험 | 시험 전에 대상 장비, 지속 시간, 입력 부하, 지연·자원 사용·중단 시간의 허용치를 기록한다. 서버 단절·인증 만료·오디오 장치 실패·파일 쓰기 실패를 시험하고 예상 중단·축소·복구 동작과 비교한다. 장시간 실행에서 큐 증가·메모리 증가·음성 겹침·자원 누수를 확인한다. |
| 11 | 설치·운영 문서 | 다른 개발자가 깨끗한 환경에서 문서만으로 잠금 설치, mock, 외부 엔진 연결, 선택 기능 설정, 검증, 장애 복구, 이전 버전 복구를 수행한다. 필요한 자산·설정·데이터 백업 및 호환성 조건을 기록한다. |
| 12 | 제한된 실방송 | 앞선 검증 후 운영자가 감독하는 제한된 방송에서 전체 흐름과 즉시 중단을 확인한다. 방송 전 시간·입력 범위·중단 조건을 정하고 사용 자산의 방송 권한을 확인한다. 결과에는 시청자 원문·비밀값을 남기지 않는다. |
| 13 | v1.0.0 배포 | 모든 필수 검증의 증거와 미해결 결함을 검토한다. 완료 기준을 막는 결함이 없어야 한다. 배포 커밋·태그, 릴리스 노트, 설치·운영·복구 문서를 확정하고 이전 버전 복구 검증을 기록한다. |

공통 자동 검증은 `uv sync --locked`, `uv run --locked pytest`, `uv run --locked ruff check .`, `uv run --locked ruff format --check .`이며, 기본 실행은 `uv run --locked python -m virtual_ai --backend mock --once "안녕"`이다. 자동 검증은 직접 청취·실제 모델 화면 확인·녹화 검토·실방송 확인을 대체하지 않는다.

## 증거와 현재 출발점

각 단계의 기록에는 검증 일시, 대상 커밋, 환경·설정 식별 정보(비밀값 제외), 실행 절차, 기대 결과, 실제 결과, 통과·실패·미확인, 남은 문제를 포함한다. 자동 테스트·실제 서버 확인·사람의 청취 및 화면 확인을 별도 항목으로 기록한다. 미실행·미확인 항목은 통과로 간주하지 않는다.

- 이번 문서 작성 시 로컬 HEAD는 `04564f1134dd330d77a164904190087ab59d1c23`, 브랜치는 `feat/youtube-chat`이다. 이는 출발점 식별이며 검증된 릴리스 기준 버전 확정은 아니다.
- 기존 [2026-09-21 작업 기록](../2026-09-21.md)과 [음성 파이프라인](voice-pipeline.md)에는 직접 청취 미확인이 명시되어 있다. [OBS 문서](obs-local-recording.md)에도 실제 모델 검증과 로컬 녹화가 미완료로 남아 있다.
- 이번 작업에서는 완료 기준과 순서만 고정한다. 자동 테스트·외부 서버·장치·원격 PR 상태를 새로 검증하지 않았으며 병합·송출·배포를 수행하지 않는다.
- 다음 실행 작업은 1단계의 기준 버전·의존 관계·검증 결과 확정이다. 이어서 2단계 직접 청취를 수행하고, 완료 전 음성 통합의 기존 Draft·병합 보류 기준을 유지한다.

## v1.0 이후 별도 확장

벡터 DB, 모델 미세조정, 다중 방송 플랫폼, 게임 자동 조작, 무인 24시간 방송은 v1.0 완료 조건에 포함하지 않는다. 세밀한 감정 표현과 OBS 자동 장면 전환도 별도 확장으로 다룬다. SQLite 기억과 마이크 STT는 이번에 정한 v1.0 필수 범위에 포함한다.

확장에 대비한다는 이유로 거대한 Router·RAG·Agent 구조를 먼저 만들지 않는다. 외부 엔진은 별도 실행하고 기존 통신·프롬프트·실행 흐름의 책임 분리를 유지한다.
