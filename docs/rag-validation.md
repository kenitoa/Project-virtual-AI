# LLM·RAG 검증 기록

검증일: 2026-09-26. Windows / 저장소의 uv 잠금 환경.
작업 위치: 기존 IDE 작업 폴더의 미커밋 변경. 기존 치지직 연동 작업을 보존했다.
요구사항·운영 명령·제한은 [LLM·RAG 구현 계획](llm-rag-plan.md)을 참고한다.

아래는 최초 RAG 구현 시점의 기록이다. 같은 날 추가한 대화 제어·근거 어미 변환과
현재 코드의 추가 검증은 [대화 확장 검증](dialogue-validation.md)을 참고한다.

| 운영 CLI 자동 회귀 | 동의 등록 → 기억 후보 생성 → 승인 → 조회 → 삭제 → 재조회 차단 통과 |
| 기본 로컬 LLM 읽기 확인 | `http://127.0.0.1:5001/v1/models` 연결 불가; 서버 실행/모델 변경 안 함 |

전체 테스트 이후 추가한 변경은 사용된 근거 ID 진단 필드이며 해당 RAG 테스트 43개와
전체 Ruff 검사를 다시 실행했다. 나머지 코드의 전체 회귀는 위 676개 결과다.

100개 평가의 상세 JSON은 Git 제외 경로 `.local/rag-evaluation-verified.json`에 있다.
동일 명령 재실행 시 새 보고서 경로를 선택해야 한다.

```powershell
python -m uv run --locked python -m virtual_ai.rag.evaluation --report .local/rag-evaluation-next.json
```

첫 평가에서는 붙여 쓴 “퍼즐게임” 검색이 실패해 99/100이었다.
일부 한국어 복합어를 분리하는 정규화를 추가한 후 100/100을 확인했다.
이 수정에 사용한 평가 세트이므로 독립적인 일반화 성능으로 해석하지 않는다.

## 직접 확인한 회귀 범위

- 닉네임이 아닌 scope·플랫폼·사용자 ID별 검색 분리.
- 저장/조회/공개 권한, 승인 전 후보 미노출, 제삼자 발언·질문·농담 보수적 제외.
- 문서 버전 불변성, 등록 실패 시 이전 활성 버전 유지, 삭제와 벡터 cascade.
- 기억 정정·거절·삭제·만료, 삭제 원장 누락/동일 사용자 재허용 거절.
- 삭제 후 RAM 대화에 남은 근거 제거, 생성 중 삭제 시 늦은 텍스트 억제.
- TTS 합성 중 자료 삭제 시 음성 재생 억제.
- 검색 중 중지, 취소와 경쟁한 후보 저장의 사후 제거.
- 실제 프로그램 상태 사용, 생성 중 운영자 상태 변경 재확인.
- 근거 ID/전체 원문 일치, 조건·예외 삭제 및 근거 없는 답변 거절.
- 검색 기능 비활성 시 해당 저장소 조회 차단, 민감한 입력 이후 작업자 정상 유지.
- 모의 HTTP 임베딩 계약, 모델별 색인, 손상된 벡터의 어휘 검색 fallback.
- 로컬 운영자 CLI의 한국어 출력과 기억 등록·승인·삭제 왕복.
- 기존 LLM·기억·음성·운영 제어·치지직을 포함한 전체 회귀.

## 실제 모델·장비 확인: 미확인

다음 항목은 자동 검증 성공에 포함하지 않는다.

1. 실제 KoboldCpp 모델이 근거 JSON 계약을 얼마나 잘 지키는지.
2. 검색된 여러 자료 중 질문에 맞는 자료 선택과 한국어 의미적 정확성.
3. 실제 모델에서의 캐릭터성·지연·GPU 자원 경합·중단 후 재사용.
4. 실제 임베딩 서버의 한국어 의미 검색 품질 및 모델별 임계값.
5. 스피커/헤드폰 직접 청취, 조건·예외의 발음·잘림·중복 재생.
6. 실제 VTS·OBS 녹화와 감독하의 방송 수용 시험.

서버를 별도로 실행하고 검증된 설정을 준비한 후 다음과 같이 실제 LLM 출력 계약을 검사할 수 있다.
이 명령도 음성 장치·캐릭터 표현·시청자 청취 수용을 대체하지 않는다.

```powershell
python -m uv run --locked python -m virtual_ai.rag.evaluation --live-config configs/app.yaml --report .local/rag-evaluation-live.json
```

실제 출력 계약 결과는 `live_output_contract`로 가상 검색 결과와 분리해 집계한다.
현재 저장된 보고서의 mode는 `synthetic_no_llm`이며 live 검사 분모는 0이다.

## 기능의 현재 한계

근거 답변은 전체 원문 발췌를 승인하는 보수적 방식이다. 자유로운 요약·재서술의 의미를
자동 입증하지 않는다. 잘못된 문서 자체를 참으로 바꿀 수 없으므로 운영자 승인 자료 품질도 필요하다.
패턴 기반 민감정보/주입 방어가 모든 새로운 공격·개인정보를 알아내지는 못한다.
자동 문서 수집, 자동 모델 설치, 신경망 재정렬기, 플랫폼 계정 연결과 셀프서비스 동의 UI는 제공하지 않는다.
원래 기획에서 평가 후 도입하기로 한 조건부 확장과 실제 수용 항목은 이 문서에서 계속 구별한다.

기본 설정은 비활성으로 유지했다. 실제 개인 정보 저장·방송 송출·원격 배포·커밋·푸시는 수행하지 않았다.
