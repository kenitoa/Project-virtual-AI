# 음성 대화의 선택적 표정 연결

`feat/vts-expression-pipeline`은 `feat/vts-client`의 `e806e1f` 위에서 분리했습니다.
독립 클라이언트의 자동 검사는 통과했지만 실제 VTube Studio 모델 화면 검증은 아직 대기입니다.
이 통합도 실제 표정 변화·복귀 완료로 기록하지 않습니다.

## 범위와 정책

`Response.expression`은 기존 `blocked` 뒤에 기본값 `neutral`로 추가했습니다.
기존 다섯 번째 위치 인자의 차단 여부 의미는 유지하고, `prepare_response()`는 키워드 인자로
응답을 생성합니다. 모델 출력은 일반 텍스트이며 모델이 핫키·동작을 지정하지 않습니다.

정책을 주입하지 않은 기본 표정은 neutral입니다. CLI는 검사된 최종 답변의 명확한 축하·공감 문구를
`conservative_expression()`으로 분류합니다. `expressions.select_expression()`은 별도의 선택 정책 경계이며,
테스트와 프로그램 호출자는 `Application(..., expression_policy=...)`에 신뢰할 수 있는 콜백을
주입할 수 있습니다. 콜백 후보는 `map_expression()`과 설정 허용 목록을 거칩니다.
차단된 답변은 정책을 호출하지 않고 neutral로 처리하고, 문자열이 아닌 값·미허용 값도 neutral입니다.
허용 후보는 neutral/happy/sad와 설정 허용 목록의 교집합입니다. 불확실·질문·인용·혼합 감정과
정책 예외는 neutral로 돌아갑니다. 의미 기반 감정 모델이 아닌 보수적인 문구 규칙이며,
[캐릭터 평가표](character-evaluation.md)의 실제 모델·화면 확인은 별도로 수행합니다.

## 설정과 순서

기존 로컬 설정을 보존하고 [VTS 인증·모델·핫키 설정](vts.md)을 먼저 완료하세요.
대화 CLI는 `tts.enabled`, `audio.enabled`, `vts.enabled`가 모두 true일 때 아바타를 생성합니다.
텍스트 전용 모드나 VTS 비활성화 상태에서는 아바타에 연결하지 않습니다.
저장 토큰으로 세션 인증만 하며 대화 실행 중 최초 승인 창을 요청하지 않습니다.
초기 연결·인증 실패는 `avatar_status=unknown recovery=manual`로 기록하고 음성 대화를 계속합니다.

```text
출력 검사 → 텍스트 표시·허용된 답변의 최근 기록 저장
→ TTS 합성 → 취소/epoch 확인
→ 검증된 expression만 적용 → 취소/epoch 재확인
→ 음성 재생 → 세션 소유 표정 복귀 → 임시 WAV 삭제
```

아바타에는 raw·speech·입력 문자열을 전송하지 않습니다. VTS 클라이언트는 추가로 모델 ID와
운영자 핫키 매핑을 검증합니다. 기존 중단 설정을 포함한 LLM·음성 설정은 그대로 적용됩니다.

## 중지·불확실한 상태·종료

- `/stop`은 epoch 증가·대기열 삭제·진행 작업 취소 후 **오디오 중단을 먼저 요청**합니다.
  아바타 응답을 기다린 뒤 오디오를 중단하는 경로는 없습니다.
- 표정 복귀는 오디오 중단 시도가 끝난 후 시작합니다. 각 적용·복귀 대기는
  `vts.request_timeout_seconds`로 제한합니다. `/stop` 명령 자체는 복귀 완료를 기다리지 않습니다.
- 정상 표정 복귀는 현재 응답의 직렬 처리 잠금 안에서 완료합니다. 반복 중지·worker 취소도
  복귀 작업을 분리해 버리지 않으므로 이전 응답의 정리가 다음 응답의 표정을 해제하지 않습니다.
- 표정 오류·시간 초과·적용 중 취소는 상태 미확인으로 기록하며 해당 앱 세션의 이후 아바타
  요청을 차단합니다. 텍스트·음성은 계속 처리합니다. 취소를 늦게 처리하는 어댑터가 있어도
  기다림 제한 후 음성은 진행하며 같은 아바타에 새 표정을 보내지 않습니다.
- 네트워크에 이미 전송된 요청은 취소해도 원격 적용 여부를 확정할 수 없습니다.
  이 경우 복귀 성공을 보장하지 않으며 VTube Studio의 해당 표정 핫키로 수동 해제하고 확인합니다.
  자동 재접속이나 취소된 표정 재전송은 없습니다. 상태를 확인한 후 앱을 재실행하면 새 세션이
  다시 인증하고 다음 표정 변경 시 현재 모델·표정 상태를 조회합니다. 이전 응답은 재생하지 않습니다.
- 종료는 `Application.shutdown()` 뒤 `AsyncExitStack`에서 아바타·재생기·TTS·LLM을 정리합니다.
  아바타 정리 오류도 상태 미확인으로 기록하고 다른 클라이언트 정리를 계속합니다.
  직접 주입한 클라이언트의 소유자는 기존 음성 계약처럼 shutdown 이후 `aclose()`를 호출합니다.

## 검증 (2026-09-22)

Windows / Python 3.14.7에서 잠금 의존성 동기화, 전체 **301개 테스트**(표정 연결 22개 포함),
Ruff 및 **50개 파일** 포맷 검사를 통과했습니다.

가짜 클라이언트로 다음을 검사합니다: 표정 기본값·위치 인자 호환, 허용 목록과 차단 응답,
TTS 이후 표정 적용 및 재생 이후 복귀, VTS 실패에도 텍스트·음성 유지, 합성 중 중지의 늦은
표정 차단, 아바타 대기 중 즉시 오디오 중단, epoch 변경 후 늦은 재생 차단, 이전 정리와 다음
응답의 격리, 시간 초과 세션 차단, 저장 토큰 연결 실패·종료 오류 시 나머지 자원 정리.

실제 VTube Studio·모델은 준비되지 않아 실서버 연결, 음성 중 표정 변화, 중지 후 화면 복귀는
**미실행·미확인**입니다. 준비 후 커밋 SHA·VTS 버전·모델·시나리오·실제 화면 변화와 복귀·실패 여부를
추가해야 합니다. 자동 테스트 통과와 실제 화면 검증을 구분하며 실모델 검증 전 병합하지 않습니다.
