### 녹화 준비와 증거

1. 실제 모델 인증·표정·수동 복구를 먼저 확인한다. 립싱크 입력 조회·모델 매핑과 조정값은
   [립싱크 문서](lipsync.md)에 기록한다.
2. OBS에서 모델 화면 → AI 출력 오디오 → 파일 자막을 하나씩 추가하고 확인한다.
   동일 출력 장치를 전역 오디오와 장면 소스 양쪽에서 캡처하지 않는다. 모니터링 출력의 재캡처도 확인한다.
3. 로컬 MKV 녹화 경로, OBS 버전·해상도·FPS·인코더·오디오 트랙을 기록한다.
   아래 기존 로컬 녹화 절차를 따르며 방송 송출은 하지 않는다.
4. 아래 시나리오를 녹화하고 정상 녹화 종료 후 **저장 파일을 다시 열어** 소리와 화면을 함께 확인한다.
   OBS 미리보기·미터·파일 생성만으로 통과하지 않는다.

## 장면 구성

OBS에서 로컬 테스트용 장면을 수동으로 만들고 다음 소스를 하나씩 확인합니다.

1. **VTube Studio 화면**: 창 캡처로 대상 VTube Studio 창을 선택합니다. 미리보기에서
   모델 전체가 보이는지 확인하고 개인 정보가 있는 다른 창이 들어오지 않게 배치합니다.
2. **AI 음성 출력 장치**: 아래 명령으로 현재 장치 목록을 조회하고 로컬 `audio.output_device`와
   대조합니다. 장치 번호는 재연결·재부팅 후 바뀔 수 있습니다.
3. **선택적 자막**: 아래 UTF-8 파일을 읽는 텍스트 소스를 모델 위에 배치합니다.

```powershell
uv run --locked python -m virtual_ai.audio --list-devices
```

OBS의 **오디오 출력 캡처** 소스에서 AI가 실제 재생하는 장치의 이름을 직접 선택합니다.
장면 소스로 그 장치를 캡처한다면 OBS `설정 → 오디오`의 동일한 전역 Desktop Audio 장치는
비활성화하고, 다른 중복 오디오 소스도 확인합니다. 소스를 하나씩 음소거해 어느 경로로 들어오는지
확인하세요. 캡처된 소리를 같은 장치로 모니터링하여 다시 캡처하지 않도록 모니터링 설정도 확인합니다.
OBS 공식 [오디오 소스 안내](https://obsproject.com/kb/audio-sources)는 같은 장치의 전역·장면 중복 캡처가
에코를 일으킬 수 있다고 설명합니다. 미터가 움직이는 것만으로 실제 녹음 품질을 통과 처리하지 않습니다.

## 선택적 답변 자막

기존 `configs/app.yaml`을 예시로 덮어쓰지 말고 다음 영역만 추가합니다.

```yaml
subtitles:
  enabled: true
  path: ../.local/obs-subtitle.txt
```

기본값은 비활성화입니다. 경로는 설정 파일 기준이며, `.local` 바로 아래의 `.txt` 파일만 허용합니다.
Git 제외 경로를 사용하고 응답 ID·사용자 입력·모델 문자열로 파일 경로를 만들지 않습니다.
하나의 앱 인스턴스만 해당 파일을 사용해야 합니다. 두 인스턴스를 동시에 테스트한다면 각각 다른 파일을 지정하세요.

앱을 시작하면 빈 파일이 생성됩니다. Windows OBS에서 **텍스트 (GDI+) → 파일에서 읽기**를 켜고
그 파일의 절대 경로를 선택합니다. 한글을 지원하는 글꼴과 줄바꿈·폭·하단 여백을 조정합니다.
공식 [텍스트 소스 문서](https://obsproject.com/kb/text-sources)에 파일 읽기 설정이 설명되어 있습니다.

`SubtitleWriter`는 `Response.final`만 UTF-8로 원자적으로 교체합니다. 화면에 표시되는 검사된 답변과
대응하며, 콘솔 전체·원시 모델 응답·speech·오류 안내는 자막으로 쓰지 않습니다.
차단된 응답은 검사 단계에서 결정된 안전한 대체 답변만 기록합니다. 파일은 현재 답변 한 건이며 누적 로그가 아닙니다.

| 시점 | 자막 정책 |
| --- | --- |
| 정상 앱 시작 | 이전 실행의 잔여 자막을 비움 |
| 출력 검사 후 텍스트 표시 | 같은 `Response.final`로 교체; TTS보다 먼저 표시 |
| 정상 재생 완료 | 다음 답변 또는 중지까지 유지 |
| LLM 오류 | 오류 문구를 쓰지 않음; 기존 자막은 다음 답변/중지까지 유지 |
| TTS·재생·VTS 오류 | 검사된 답변 유지; 오류 안내는 콘솔/로그에만 표시 |
| `/stop`, `/forget` | 오디오 중단 시도 후 비움; 콘솔 텍스트·기록 정책과는 별개 |
| `/quit`, EOF, Ctrl+C, `--once` 종료 | 앱 정리 과정에서 비움 |
| 파일 쓰기/비우기 실패 | `subtitle_status=update_failed state=unknown`; 텍스트·음성은 계속 처리 |

기존 답변의 늦은 중지 정리가 새 답변 자막을 지우지 않도록 응답 ID를 대조합니다.
파일 잠금 등으로 교체/비우기가 실패하면 OBS에 이전 자막이 남을 수 있습니다. 화면을 직접 확인하고,
필요하면 자막 소스를 숨기고 파일 사용 상태를 확인하세요. 강제 프로세스 종료·전원 차단은 정상 정리가
아니므로 다음 성공적인 앱 시작 전까지 잔류할 수 있습니다. 자막은 단어별 발화 타이밍에 동기화하지 않습니다.

## 로컬 녹화 절차

선행 표정·립싱크 검증 결과를 먼저 `docs/vts.md`, `docs/lipsync.md`에 기록합니다.
그다음 LLM·GPT-SoVITS·VTube Studio·OBS를 함께 실행하고 기존 대화 명령을 사용합니다.

```powershell
uv run --locked python -m virtual_ai --config configs/app.yaml --backend koboldcpp
```

OBS `설정 → 출력`에서 로컬 녹화 경로와 실제 사용한 해상도·FPS·인코더·오디오 트랙을 기록합니다.
녹화는 Git에서 제외된 `recordings/` 또는 저장소 밖에 보관합니다.
처음에는 MKV를 사용하고 필요하면 OBS의 녹화 리먹스로 MP4를 만듭니다.
OBS [녹화 안내](https://obsproject.com/kb/standard-recording-output-guide)는 비정상 종료에 대비해 MKV를 권장합니다.
**방송 시작이 아닌 녹화 시작**을 누르고, 아래 시나리오를 짧게 녹화한 뒤 중지합니다.

| 시나리오 | 녹화 파일을 다시 보며 확인할 기준 | 현재 결과 |
| --- | --- | --- |
| 일반 한국어 답변 | 자막·음성이 대응, 음성 크기와 입 움직임이 대체로 대응, 잘림·잡음·무음 없음 | 미실행 |
| 재생 완료 | 입 벌림·프로그램 소유 표정이 복귀, 자막은 정책대로 유지 | 미실행 |
| 재생 중 `/stop` | 소리 중단, 입·표정 복귀 여부, 자막 삭제를 각각 확인 | 미실행 |
| `/stop` 후 다음 질문 | 새 음성·입 움직임·자막 정상, 이전 값이 뒤늦게 나타나지 않음 | 미실행 |
| 합성/생성 중 `/stop` | 취소된 답변·음성이 뒤늦게 나타나지 않음; LLM 중단 설정의 보호 동작 구분 | 미실행 |
| 재생 중 `/quit` | 소리 중단·자막 삭제·입/표정 상태 확인, 재실행 후 출력 장치 재사용 | 미실행 |
| 오디오 경로 | 이중 음성·에코 없음, 의도한 장치·트랙에서 한 번만 캡처됨 | 미실행 |
| 오류 상황 | 오류 안내가 자막에 노출되지 않음, VTS 연결 실패 시 화면 복귀는 미확인으로 기록 | 미실행 |

OBS 미리보기·오디오 미터·API 성공 로그와 **저장된 녹화의 실제 재생 확인**은 구분합니다.
저장 파일을 열어 듣고 보며 해당 구간의 타임스탬프, 들린 소리, 입/표정/자막 상태, 실패 여부를 기록하세요.
관측하지 못한 항목은 미확인으로 남깁니다.
