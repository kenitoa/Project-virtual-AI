## 실제 시험에서 발견한 문제와 수정

1. 모델이 “잘 지냈어?”를 “잘 지냈어요?”로 되물었고, 시청자의 합격을 자신의 일처럼 감사하는 출력도 있었다.
   캐릭터 예시를 정리하고 이 두 가지 관측된 오류에 한정한 출력 검사를 추가했다. 광범위한 의미 정확성 검증이라고 주장하지 않는다.
2. UUID 두 개를 출력해야 하는 복합 근거 질문이 두 번째 실제 평가에서 10초를 넘겼다(23/24).
   해당 턴은 늦은 출력 없이 차단됐지만 응답 성공은 아니었다. 모델에는 턴 내부의 `s1`, `s2`만 제공하고 검증 후 원래 ID로 복원하도록 변경했다.
   알 수 없는 번호·같은 근거의 번호/원본 ID 중복·범위 밖 출처를 거부하고, 진단·기억 쿨다운에는 원래 ID를 기록한다.
   수정 후 같은 실제 평가가 24/24로 통과했다. UUID 방식 첫 회의 p95 5.46초에서 최종 2.78초로 줄었지만 반복 횟수가 적어 통계적 성능 보장은 아니다.
3. 생성 시작 직후 매우 이른 취소 시험에서는 서버가 해당 키의 정리를 확정하지 못하는 경우가 있었다.
   앱은 다음 생성을 차단하고 일시 정지했다. 실패를 성공으로 바꾸거나 잠금을 자동 해제하지 않았다.
   별도 시험에서 실제 생성 활성 상태를 확인한 뒤 중단·유휴 확인·다음 응답을 검증했다.
4. TTS 첫 합성 23초는 공개 응답 유효 시간 기본 20초보다 길다.
   예열 없이 방송 첫 질문부터 음성을 기대하면 늦은 음성이 차단될 수 있다. 엔진 시작 후 고정 문장 예열을 먼저 수행한다.
5. 기존 긴 원문 인용 계약의 실제 출력은 60개 중 49개만 통과했다. 나머지 11개는 unsupported로 차단됐다.
   평가기도 활성화된 새 생성 계약을 사용하지 않는 문제가 있어 수정했다.
   원문을 모델이 다시 복사하는 대신 근거 번호만 생성하는 방식을 RAG 공통 경로로 승격했다. 새 계약 실제 재검증은 60/60이다.
   `--legacy-quotes`는 이전 계약의 실패를 재현하는 비교 진단 옵션이며 방송 생성 경로로 사용하지 않는다.

## 재현 및 증거 위치

Git 제외 `.local/live-verification/`에 엔진 로그, 파일 해시, 실제 모델 보고서, 합성 대화 원문, WAV, 제한·중단·구독 결과를 보관했다.
실제 시청자 채팅은 보관하지 않았다.
검증 종료 시 idle=1/queue=0을 확인한 뒤 이번에 시작한 엔진 PID와 실행 파일·부모 PID를 대조하여 종료했다.
5001/9880 리스너가 남지 않은 것을 확인했다. 리허설 재실행 전 엔진을 다시 시작하고 예열해야 한다.
최종 Ruff check 및 format(157개 파일), git diff --check도 통과했다.

- `dialogue-actual.json`: 최초 실제 24턴 평가, 원래 UUID 방식.
- `dialogue-after-fix.json`: 복합 질문 시간 초과가 나타난 23/24 실행. 실패 증거를 보존한다.
- `dialogue-compact-ids.json`: 짧은 근거 번호를 적용한 최종 24/24 실행.
- `rag-actual.json`: 이전 원문 복사 계약 49/60. `rag-compact-actual.json`: 새 계약 60/60 및 전체 논리 검사 100/100.
- `rag-without-dialogue.json`: 대화 옵션 비활성 상태의 실제 새 계약 검증.
- `runtime.json`: 추가 8개 대화, 실제 제한·큐 집중·중단·재개.
- `abort.json`, `voice.json`, `chzzk.json`, `asset-hashes.json`, `startup-diagnostics.json`.
- `local-rehearsal.yaml`: 검증한 로컬 엔진·음성·대화 설정. 외부 채팅 비활성, 원래 `configs/app.yaml`은 변경하지 않았다.

엔진은 [백엔드 실행 방법](backends.md)에 따라 별도로 시작한다. 예열은 소리 재생 없이 WAV만 만든다.

```powershell
python -m uv run --locked python -m virtual_ai.tts --config .local/live-verification/local-rehearsal.yaml --output .local/live-verification/warmup.wav
python -m uv run --locked python -m virtual_ai --config .local/live-verification/local-rehearsal.yaml --local-only --dialogue
```

리허설 설정에는 실제 방송 지식이나 시청자 기억을 자동 등록하지 않았다. 승인된 방송 자료를 준비한 뒤 RAG를 별도로 활성화한다.
평가용 질문을 실제 방송 지식으로 승격하지 않는다.
