# 방송 운영 제어

운영 명령은 로컬 콘솔에서만 실행한다. 시청자·YouTube·모델의 같은 문자열은 대화 데이터다.
불변 설정과 별개로 `RuntimeState`가 실행 상태를 관리한다.

| 명령 | 동작 |
| --- | --- |
| `/pause` | 입력 잠금을 먼저 설정하고 현재 응답·대기열·재생을 중단한다. 이후 입력은 버린다. |
| `/resume` | 비상 잠금·진행 중 처리/정리·정리 실패·LLM 정리 불명이 없을 때 입력 처리 재개. 음소거는 유지한다. |
| `/mute` | 음소거·음성 세대를 먼저 변경하고 합성/재생을 취소한다. 이후 텍스트 대화는 계속하고 음성은 만들지 않는다. |
| `/unmute` | 비상 잠금·진행 중 처리/정리·정리 실패가 없을 때 이후 응답의 음성을 허용한다. 지난 음성을 재생하지 않는다. |
| `/status` | paused/panic/muted, 단계(idle/llm/tts/playback), 큐, 정리 여부, 외부 상태를 출력한다. |
| `/panic` | 입력과 음성을 먼저 잠그고 현재 응답·대기열을 취소한다. resume/unmute로 해제할 수 없다. |
| `/recover` | 정리가 확인된 경우에만 비상 잠금을 해제한다. 여전히 paused·muted이므로 명시적인 resume·unmute가 필요하다. |

`/stop`은 기존처럼 현재 응답·큐만 취소하며 새 입력을 잠그지 않는다. 이미 pause/panic 상태라면
그 잠금을 해제하지 않는다. `/forget`은 중단 후 최근 기록 삭제, `/quit`은 자원 정리 후 종료를 유지한다.

## 방송 시작과 복구

```powershell
python -m uv run --locked python -m virtual_ai --config configs/app.yaml --backend koboldcpp --live
```

`--live` 또는 YouTube 수신 활성화 시 **기본 일시 정지**로 시작한다. 일반 로컬 대화와 mock은
기존 기본 동작을 유지한다. `--live --once` 조합은 거부한다. 재시작 때 이전 비상 상태를 저장하지는
않으므로 방송에서는 반드시 이 시작 조건을 사용한다. 준비 상태를 확인한 운영자가 `/resume`한다.

일시 정지·비상 정지 중 YouTube 수신 위치는 계속 갱신하되 앱은 입력을 버린다. 재개 시각보다
오래된 게시 시각의 메시지는 늦게 수신되어도 버리므로 정지 기간 채팅이 몰아서 발화되지 않는다.
이를 위해 PC 시각이 정확해야 한다. 버린 입력은 복원하지 않는다.

비상 정지 후 `/status`를 확인하고 `/recover` → `/resume` → `/unmute`를 명시적으로 수행한다.
처리가 아직 진행 중이면 복구 명령은 기다리며 잠금을 풀지 않고 즉시 거부한다. 장치 정리 실패나
임시 WAV 삭제 실패는 잠금을 유지하므로 원인과 실제 소리를 확인한 뒤 앱을 재시작한다.
KoboldCpp `cleanup_unconfirmed`도 recover로 우회하지 않는다. 서버 idle=1/queue=0 확인 또는
운영자의 서버 정리 후 앱 재시작이 필요하다. TTS 요청 취소는 서버 내부 합성 중단을 보장하지 않는다.

`status`는 연결 상태를 검사하기 위해 네트워크 요청을 보내지 않는다. `not_probed`는 현재 연결을
확인하지 않았다는 뜻이며 정상 연결을 의미하지 않는다. VTS `session_available`도 살아 있는 세션의
로컬 관측일 뿐 실시간 화면/연결 정상 보장은 아니다. 인증 토큰·모델 응답·사용자 정보는 출력하지 않는다.

## OBS 수동 비상 음소거

앱·장치 장애에 대비해 OBS 오디오 믹서에서 **AI 출력 캡처 소스의 스피커 버튼**으로 직접
음소거하는 경로를 운영자가 확보한다. AI 소스를 명확히 이름 붙이고 같은 장치의 전역/장면
중복 캡처를 없앤다. 필요하면 OBS에서 해당 소스 음소거 단축키를 운영자가 지정한다.
앱 mute는 OBS 조작이나 시스템 볼륨 변경이 아니므로 이미 버퍼에 들어간 소리의 즉시 무음을
보장하는 독립 안전장치로 간주하지 않는다.

실방송 전에 로컬 MKV를 녹화하며 앱을 조작할 수 없는 상황에서도 OBS 수동 음소거가 녹음 트랙을
무음으로 만드는지 직접 듣고 확인한다. 현재 사용자는 VTS·OBS 미준비로 답했으므로 **수동 경로의
실환경 확보·검증은 대기**다. 이 문서를 작성한 것을 실제 확보 완료로 취급하지 않는다.

## 검증 범위

자동 검사에서 LLM·TTS·재생 지연 중 panic, 정리 중 입력/복구 거부, 늦은 합성 재생 차단,
mute 중 텍스트 유지, 복구 순서, 정리 실패 시 차단, 시청자·모델 명령 분리, 지연된 채팅의 재개 후
폐기와 수신 위치 갱신을 확인한다. 실장치 음성 중단·OBS 무음은 별도 직접 청취가 필요하다.
