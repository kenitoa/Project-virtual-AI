# 재생 PCM 기반 VTube Studio 립싱크

`feat/vts-lipsync`는 `feat/vts-expression-pipeline`의 `c82ab11` 위에서 분리했습니다.
첫 버전은 음소·발음 분석 없이 출력 PCM의 크기로 입 벌림 값을 만듭니다.
실제 VTube Studio 모델 자산은 준비되지 않았으므로 화면 동기화는 미검증입니다.

## 운영자 설정

기존 `configs/app.yaml`을 보존하고 `vts` 영역에 다음 항목을 추가합니다.
사용하려면 기존 `tts.enabled`, `audio.enabled`, `vts.enabled`도 true여야 합니다.

```yaml
vts:
  # 기존 URL·플러그인·토큰·모델·표정 설정 유지
  lipsync_enabled: false
  mouth_parameter: ""
  lipsync_hz: 25
  lipsync_gain: 4
  lipsync_smoothing: 0.4
```

기본 비활성화이며 의존성 추가는 없습니다. `lipsync_hz`는 20~30Hz,
gain은 0 초과~20, smoothing은 0 초과~1입니다. gain은 RMS에 곱한 뒤 0~1로 제한하고,
smoothing은 이전 값과 새 값의 지수 평활 가중치입니다. 무음·측정 만료는 즉시 0으로 처리합니다.

먼저 [독립 VTS 인증](vts.md)을 완료하고 현재 입력 파라미터를 조회합니다.

```powershell
uv run --locked python -m virtual_ai.integrations.vts --config configs/app.yaml --list-parameters
```

실제 `modelID`를 `expected_model_id`에, 사용할 **VTS 입력 파라미터 이름**을 `mouth_parameter`에
설정합니다. 기본 또는 이미 존재하는 사용자 정의 파라미터를 사용할 수 있습니다.
이름을 임의의 Live2D ID로 가정하지 않습니다. 모델 설정 화면에서 그 입력을 해당 모델의
입 벌림 출력에 연결하고, 입력 0이 닫힘·1이 열림에 대응하도록 범위를 확인하세요.
이 구현은 사용자 정의 파라미터 생성이나 Live2D 매핑 변경을 자동 수행하지 않습니다.

`lipsync_enabled: true`로 바꾼 후 기존 대화 CLI를 실행합니다.

```powershell
uv run --locked python -m virtual_ai --config configs/app.yaml --backend koboldcpp
```

VTS 클라이언트는 모델 ID와 입력 파라미터 목록·0~1 지원 범위를 검증합니다.
입력 파라미터 검증은 세션에서 한 번, 모델 ID는 매 전송 전에 확인합니다.
[공식 InjectParameterData API](https://github.com/DenchiSoft/VTubeStudio#feeding-in-data-for-default-or-custom-parameters)의
`mode: set`, 단일 허용 파라미터, `weight: 1`로 값을 전송하며 얼굴 감지 상태는 변경하지 않습니다.
같은 입력을 다른 플러그인이 제어하면 오류가 날 수 있으므로 중복 제어를 피하세요.

## 재생 시계와 전송

```text
PortAudio 출력 콜백의 실제 PCM 버퍼
→ 제한된 RMS 계산 → 최신 값 한 개 교체
→ 비동기 작업의 gain·0~1 제한·평활화
→ 유효한 현재 재생인지 재확인 → VTS 파라미터 전송
```

- 지원하는 8-bit unsigned 및 16/24/32-bit signed PCM, 모노·스테레오를 처리합니다.
  스테레오는 반대 위상이 상쇄되지 않도록 개별 샘플 제곱을 사용합니다.
  콜백 부담을 제한하려고 최대 2048개 샘플을 사용하며 큰 버퍼는 간격을 두고 표본화합니다.
- 콜백 안에서 WebSocket·asyncio 작업 생성·대기열 추가를 하지 않습니다. 작은 공유 슬롯만 갱신합니다.
  미터 계산 실패는 오디오 재생을 중단하지 않습니다.
- 전송 작업은 매 주기 최신 값만 읽습니다. 느린 요청 중의 값은 덮어쓰고 응답 뒤 다시 읽으며
  누적된 오래된 프레임을 따라잡는 전송은 없습니다. 25Hz는 상한이며 응답 지연 시 실제 빈도는 낮아집니다.
- 첫 출력 콜백 전에는 입 벌림 값을 보내지 않습니다. WAV 합성 완료 시간이나 WAV 길이만큼의
  sleep을 동기화 기준으로 사용하지 않습니다. 출력 콜백이 중단되면 해당 버퍼 시간 + 100ms 후 0을 선택합니다.
- 기준은 **장치에 출력 버퍼를 전달하는 콜백 시각**입니다. DAC의 실제 첫 소리 시각과 완전히
  같은 것은 아니며 장치 버퍼·VTS 네트워크·모델 평활화 지연이 남습니다. 실제 모델에서 확인해야 합니다.

## 중지·오류·종료

재생마다 별도 슬롯을 만들며 종료 후 슬롯은 닫힙니다. 이전 재생 콜백이 늦게 값을 써도
새 재생에 전달되지 않습니다. epoch와 중지 상태는 전송 직전 및 VTS 모델 조회 후에도 확인합니다.

`/stop`은 슬롯 갱신과 새 입 움직임 요청을 차단하고 기존처럼 오디오 중단을 우선합니다.
일반 종료·중지·재생 실패 모두 진행 중 전송이 제한 시간 내 끝나길 기다린 뒤 0을 보내고
표정 정리·WAV 삭제로 이어집니다. 클라이언트 종료에도 제어 중인 입 값의 0 복귀 경로가 있습니다.

VTS 연결 실패·시간 초과는 `avatar_status=unknown recovery=manual`로 기록하고 음성은 유지합니다.
이미 서버로 보낸 값의 원격 적용을 취소할 수는 없습니다. 연결이 끊겼거나 정리를 확인하지 못하면
**입이 닫혔다고 처리하지 않습니다.** 자동 재연결·실패 값 재전송은 없습니다.
공식 API는 갱신이 약 1초 이상 끊기면 기존 추적 입력 또는 기본값으로 돌아갈 수 있으므로,
0을 한 번 전송한 뒤 계속 영구적으로 닫힘을 강제하는 기능도 아닙니다.
VTS 화면에서 입력/출력 매핑과 기존 추적 상태를 확인하고 필요하면 해당 매핑을 수동 비활성화하세요.

## 검증 기록 (2026-09-22)

Windows / Python 3.14.7에서 잠금 의존성 동기화, 전체 **337개 테스트**
(립싱크 35개 및 파라미터 조회 CLI 검사 포함), Ruff 및 **54개 파일** 포맷 검사를 통과했습니다.

자동 테스트는 PCM 형식·무음·스테레오 RMS, 실제 재생기 가짜 장치 콜백,
콜백 이전 미전송, 최신 값 교체·만료·평활화·전송 빈도, 재생 완료·중지·종료·재생기 오류의 0 복귀,
이전 재생의 늦은 업데이트 차단, 모델 조회 도중 취소, VTS 오류·지연 중 음성 유지,
입력 파라미터·모델·범위 제한을 확인합니다.

실제 모델·입 파라미터 매핑, 실제 음성과 화면의 지연, `/stop`·`/quit` 후 화면 복귀는
**미실행·미확인**입니다. 모델 준비 후 커밋 SHA, VTS 버전, 모델·입력 이름·매핑,
출력 장치, Hz/gain/smoothing, 시나리오별 화면 변화·실패 여부를 기록하세요.
자동 테스트 성공을 실제 립싱크 완료로 대체하지 않으며 실제 검증 전 병합하지 않습니다.
