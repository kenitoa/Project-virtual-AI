# 텍스트 대화 구조

터미널 → 제한 대기열 → 시스템 정책·캐릭터·최근 기록·입력 → LLMClient
→ 원시 응답 추출 → 출력 정책 검사 → 최종 텍스트·음성용 문자열.
HTTP 통신은 KoboldCppClient, 프롬프트는 prompting, 순서·취소는 Application이 담당합니다.
모델 실행·음성 합성·방송 도구는 프로세스에 포함하지 않습니다.

## 제한과 기록

- 큐가 가득 차면 가장 오래된 입력을 버립니다. TTL이 지난 입력도 제외합니다.
  플랫폼·사용자·메시지 ID가 같은 중복은 TTL 동안 제한된 캐시에 의해 거절됩니다.
- 사용자별 성공한 입력과 검사된 최종 답변 쌍만 RAM에 보관합니다. 추론 원문·오류·차단·취소 결과는 보관하지 않습니다.
- 기본 한도는 사용자 100명, 사용자별 6턴·6000자, 마지막 성공 대화부터 3600초입니다.
  조회·추가 시 만료를 정리하며, 사용자 초과 시 가장 오래 갱신된 사용자를 제거합니다.
- `/forget`은 현재 작업 무효화·취소 후 전체 최근 기록을 지웁니다. 내부 API는 특정 Viewer 삭제도 지원합니다.
  `/stop`은 기록을 지우지 않습니다. 종료하면 RAM 기록은 사라지며 DB·파일·요약 기억은 만들지 않습니다.
- 컨텍스트는 출력 토큰을 먼저 예약하고 UTF-8 바이트 수 + 메시지당 32 + 템플릿 256의 추정 예산으로 제한합니다.
  오래된 대화 쌍부터 제외하며 시스템 정책·현재 요청은 자르지 않습니다. 실제 토크나이저와 템플릿 검증은 별도입니다.

## 보안과 실패 처리

설정 파일과 CLI는 로컬 운영자가 관리합니다. 시청자·모델 입력은 데이터로만 처리하며
셸·파일·OBS 제어 명령으로 실행하지 않습니다. 알려진 비밀값 패턴은 프롬프트 전송 전에 차단합니다.
이는 패턴 기반 보조 방어이며 모든 민감정보를 판별하는 기능은 아닙니다.
통신 오류는 제한된 안내만 출력하며 원문·답변·사용자 식별자는 로그에 기록하지 않습니다.

LLM 요청은 하나씩 처리합니다. `/stop`은 큐를 비우고 epoch를 변경한 다음 현재 생성 Task를 취소합니다.
응답 한 건의 취소는 worker 종료로 전파하지 않지만 worker 자체의 취소는 전파합니다.
epoch가 달라진 늦은 결과는 출력·기록하지 않습니다. Python 요청 취소가 서버 GPU 중단을 보장하지는 않습니다.

설정·프롬프트 파일은 시작 시 검증하며 초기화 실패 시에도 생성된 클라이언트를 닫습니다.
실패 시 mock으로 대체하지 않습니다. 단발 LLM 실패는 종료 코드 1, 설정/입력 오류는 2입니다.
대화형 실행은 오류 안내 후 다음 입력을 받습니다.

모든 설계 항목의 반영·후속·미검증 상태는 [skill 적용 현황](skill-coverage.md),
실제 외부 엔진 검증은 [백엔드 기록](backends.md)을 참고하세요.
