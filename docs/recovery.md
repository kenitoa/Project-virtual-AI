# 업데이트·종료 후 복구

## 업데이트 전

1. `/pause` 후 `/quit`으로 앱을 정상 종료한다. 다른 PC·프로세스도 같은 DB를 사용하지 않도록 한다.
2. 운영자 로컬 설정을 비공개 백업하고 외부 엔진 버전·모델 해시·현재 Git 커밋을 기록한다.
3. 기억을 사용한다면 **업데이트 전 코드**에서 백업한다. Git pull이나 체크아웃부터 하지 않는다.

```powershell
python -m uv run --locked python -m virtual_ai.memory --db C:\VirtualAIData\memory.sqlite3 --enabled backup --file C:\VirtualAIData\backups\before-update.sqlite3
```

대상 파일은 존재하지 않아야 한다. SQLite 백업 API를 사용하며 실행 중 메인 DB 파일을 그냥 복사하지 않는다.
현재 삭제 원장 `memory.sqlite3.deletions.sqlite3`는 메인 DB와 별개로 보호하고 최신 상태를 유지한다.
OS 백업이 필요하면 모든 작성자를 종료한 상태에서 운영자 보관 정책에 따라 수행한다.

4. 로컬 수정 사항이 있으면 별도 체크아웃을 준비한다. `git clean -xfd`, 설정 덮어쓰기, 런타임 폴더 삭제를 하지 않는다.
5. 새 코드에서 bootstrap·진단·로컬 mock을 통과시킨 후 로컬 설정에 필요한 필드만 직접 반영한다.
6. 기억 DB는 처음 열 때 스키마를 검사한다. 현재 v1→v2는 마이그레이션 전에 같은 폴더에
   `memory.sqlite3.pre-migration-UUID.sqlite3`를 SQLite API로 만든다. 백업 실패 시 원래 DB를 업그레이드하지 않는다.
   공간·권한을 해결한 후 재시도한다. 실패한 부분 백업 파일은 정상 백업으로 사용하지 않는다.

새 PC·새 체크아웃에서도 런타임 데이터는 `C:\VirtualAIData` 같은 별도 비공유 로컬 경로에 두고
명시적 `-MemoryDb`로 연결한다. 저장소의 `.local`을 쓰면 체크아웃을 바꿀 때 자동 이전되지 않는다.
앱이 실행 중인 동안 업그레이드·DB 복구를 수행하지 않는다.

## 코드 롤백과 DB 롤백은 별개

- **코드만 롤백:** 이전 커밋의 별도 체크아웃과 해당 `uv.lock`으로 환경을 준비한다. 운영 설정은 보존한다.
  새 DB 형식을 옛 코드가 읽을 수 있다고 가정하지 않는다. `unsupported_schema`라면 실행을 멈춘다.
- **같은 DB 형식 복원:** 현재 코드의 `memory restore --file ...`를 오프라인에서 사용한다.
  저장소 ID·스키마 체크섬을 검사하고 **현재 삭제 원장**으로 삭제 및 만료를 다시 적용한다.
- **이전 DB 형식으로 복원:** 현재 restore는 다른 스키마를 거절한다. 자동 downgrade는 제공하지 않는다.
  운영 DB를 덮어쓰지 말고 업그레이드 전 백업을 별도 복구 폴더에 준비한다. 그 백업과 호환되는 코드에서
  현재 삭제 원장을 유지한 상태로 저장소 ID·삭제 후 미조회·마이그레이션 정책을 검증한 후 전환한다.
  검증하지 못하면 이전 DB로 전환하지 않는다. 최신 코드로 복구하거나 별도 데이터 이전 작업이 필요하다.

옛 백업의 삭제 원장으로 현재 원장을 되돌리면 삭제 데이터가 살아날 수 있다. 이를 허용하지 않는다.
백업 원문 폐기와 삭제 요청 처리는 [개인정보·보관](privacy-and-retention.md)을 따른다.

## 비상 종료 뒤

1. OBS 오디오를 음소거하고 수신·응답이 중지됐는지 확인한다.
2. 소유한 앱의 종료를 확인한다. 외부 엔진·OBS·VTS는 별도 프로그램이며 종료 스크립트가 관리하지 않는다.
3. KoboldCpp 생성/정리 상태를 확인한다. 서버 중단 지원이 검증되지 않았다면 임의 API 호출 대신
   해당 엔진의 문서화된 중단·재시작으로 수동 복구한다.
4. VTS의 남은 표정·입 상태를 직접 복구한다. 새 프로세스의 neutral이 이전 세션 표정을 지운다고 가정하지 않는다.
5. STT가 실행 중이었으면 그 작업의 프로세스 식별자를 확인해 별도 관리한다. Python 전체 종료는 하지 않는다.
6. 임시 WAV·자막·STT 임시 디렉터리를 확인하고 사용 중인 파일이 아님을 검증한 뒤 해당 파일만 정리한다.
7. 진단 후 live 모드로 재실행하고 일시 정지 상태에서 `/status`를 확인한다. 운영자가 명시적으로 재개한다.

DB 손상·삭제 원장 유실은 새 빈 원장 생성으로 우회하지 않는다. 보호된 최신 원장을 복구하거나
장기 기억을 비활성화하고 조사한다. 실제 장치 제거·강제 종료 뒤 청취와 OBS 녹화 확인은 아직 수용 검증 대기다.
