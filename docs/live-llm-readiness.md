## 시청자 입력과 LLM 반응

- “퇴근하고 왔어”, “오늘 피곤해서 쉬러 왔어”, “잘 지냈어?”는 일상 대화로 LLM에 전달한다.
- “너는 참여 규칙 알려줘, 실패해서 속상해”는 사실 질문이 우선이다. RAG가 켜져 있으면 승인 근거를 조회하고 조건·예외를 보존해 답한다.
- “합격했어! 참여 조건은?”도 감탄 한 문장으로 잘라서 질문을 놓치지 않도록 근거 답변 경로를 사용한다.
- “속상하지 않아, 합격했어”처럼 부정된 감정 표현을 일부 구분한다. 복잡한 반어·은유의 완전한 이해를 보장하지 않는다.
- 단순 인사·웃음의 동일 표현은 변주하지만, 내용이 있는 답이 반복됐다는 이유만으로 빈 확인 약속으로 바꾸지 않는다.
- 현재 시청자의 질문을 먼저 답하고, 확인하지 않은 방송 장면·기억·권한을 지어내지 않도록 프롬프트를 정리했다.

검색 근거에서 모델에 필요한 ID·종류·제목·원문·출처·버전만 전달한다. 권한·만료·삭제 확인은 원래 자료로 계속 수행한다.
선택 대화 맥락을 예산 때문에 제외하면 그 맥락에만 쓰는 규칙도 함께 제외한다.
기본 4,096 문맥 설정에서 참여 규칙과 퍼즐 설명을 함께 묻는 합성 사례를 검증했다.

## 생성 시간과 늦은 응답

`dialogue.enabled: true`인 공개 플랫폼 채팅에 적용한다. console은 기존 전체 호출 제한을 유지한다.

```yaml
dialogue:
  enabled: true
  generation_timeout_seconds: 10
  public_response_ttl_seconds: 20
```

1. 게시 시각과 앱 접수 시각으로 메시지 나이를 계산한다. 대기열·검색 시간도 유효 시간에 포함한다.
2. 이미 20초가 지난 질문은 생성 전에 버린다. 생성에는 남은 유효 시간과 10초 중 짧은 시간을 적용한다.
3. 생성 제한을 넘기면 취소를 전달하고 늦은 답변을 표시·기록하지 않는다. 실제 어댑터의 중단 정리 시간이 추가될 수 있다.
4. KoboldCpp는 기존 요청별 genkey 중단 → idle=1, queue=0 확인 계약을 유지한다. 확인되지 않으면 공개 채팅 처리를 일시 정지하고 대기열을 비운다.
5. 표시 직전과 음성 합성 후 재생 시작 전에 유효 시간을 재확인한다. 이미 표시한 텍스트는 남을 수 있지만 늦은 음성은 시작하지 않는다. 이미 재생 중인 문장을 이 시간 제한만으로 중간 절단하지 않는다.

10초/20초는 설정 가능한 초기 운영 제한이며 실제 GPU의 생성 속도를 보장하는 값이 아니다.
TTS 합성 자체의 제한은 기존 TTS 설정을 따른다. 음성 파이프라인 전체 지연은 별도 측정해야 한다.
`/status`의 dialogue.mode에 skip_expired 또는 skip_generation_timeout이 기록된다.
시간 초과 시 긴 사과 문장을 자동 생성하거나 추가 모델 호출을 반복하지 않는다.

`server_abort_enabled: false` 상태에서 생성 취소가 발생하면 서버 정리를 확인할 수 없어 이후 생성을 차단한다.
실제 서버의 요청별 중단 계약을 검증한 다음 활성화해야 한다. 자세한 조건은 [백엔드 문서](backends.md)를 따른다.
설정만 켠 것을 검증 완료로 취급하지 않는다.

## 모델 생성 설정

```yaml
llm:
  backend: koboldcpp
  temperature: 0.65
  top_p: 0.9
```

두 값은 실제 `/v1/chat/completions` 요청으로 전달한다. 미설정 또는 null이면 해당 필드를 생략하여 서버 기본값을 유지한다.
temperature는 0~2, top_p는 0 초과~1이며 NaN·무한대·문자열·불리언을 거부한다.
위 값은 비교 실험의 시작값이다. 모델 가중치를 학습하거나 방송 최적값을 확정한 것은 아니다.
[KoboldCpp v1.121 공식 소스](https://github.com/LostRuins/koboldcpp/blob/v1.121/koboldcpp.py)의 transform_genparams와 생성 파라미터 처리에서 지원을 확인했다.
다른 서버 버전의 동작은 별도 검증한다.

같은 모델·양자화·엔진·컨텍스트로 설정 하나씩 바꿔 [모델 비교 CLI](dialogue-development.md)의 live-config 평가를 실행한다.
보고서에는 temperature/top_p 실제 설정을 남긴다. 이 밖의 서버 샘플링 값과 실제 로드된 GGUF는 운영자가 따로 기록한다.

## 검증 및 실제 방송 판정

합성 대화 평가는 12개 시나리오/24턴으로 확대했다. 감정이 섞인 사실 질문, 일상 대화, 부정 표현, 복수 근거 질문을 추가했다.
스크립트 LLM 결과는 실제 모델의 자연스러움 점수가 아니다.

```powershell
python -m uv run --locked pytest tests/test_live_dialogue.py tests/test_dialogue.py tests/test_koboldcpp.py -q
python -m uv run --locked python -m virtual_ai.dialogue_evaluation --report .local/dialogue-next.json
python -m uv run --locked python -m virtual_ai.dialogue_evaluation --live-config configs/app.yaml --report .local/dialogue-live-next.json
```

이번 실행 증거:

- 새 생방송 경로 테스트 22개 통과. 실제 HTTP 어댑터를 모의 서버에 연결해 요청 키 중단·정리 성공 후 재개·정리 실패 후 일시 정지를 검증했다.
- 대화 합성 평가 24/24. 복합 질문의 첫 실행은 23/24였고, 불필요한 근거 메타데이터와 남은 맥락 규칙을 줄인 후 통과했다.
- 최종 보고서: `.local/dialogue-live-hardening-final.json`, `.local/rag-live-hardening-final.json`.
- 실제 로컬 엔진 확인 명령은 실행 환경의 자동 승인 검토에서 `blocked by policy`로 거절됐다. 구체적 사유는 제공되지 않았다. 실제 생성·모델 조정·장치 송출은 검증하지 못했다.

최종 전체 회귀: **722 passed, 9 subtests passed**, 69.08초.
`uv sync --locked`, `ruff check .`, `ruff format --check .`(최종 156개 파일), `git diff --check` 통과.
기존 RAG 합성 평가 **100/100**, 검색 대상 **45/45** 통과. 새 의존성·DB 마이그레이션 없음.

방송 가능 판정에는 아래 증거가 추가로 필요하다.

| 확인 항목 | 합격 기준 / 현재 상태 |
| --- | --- |
| 실제 모델 대화 | 고정 세트와 별도 미사용 질문에서 사실 오류·질문 누락·잘못된 화자 참조를 검토. 현재 미검증 |

| 음성·표정·OBS | 직접 청취 및 로컬 녹화에서 조건·예외 발음, 지연, 중복·늦은 음성, 표정 일치를 확인. 현재 미검증 |
| 개인정보·운영 제어 | 실제 계정 권한·동의·삭제와 운영자의 pause/stop/panic 절차를 확인. 자동 시험이 실제 계정 점검을 대체하지 않음 |
