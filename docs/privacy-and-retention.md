# 설정·개인정보·보관 범위

| 구분 | 예 | 운영 원칙 |
| --- | --- | --- |
| Git 예시 | app.example.yaml, character.yaml, 합성 시험 fixture | 비밀값·실제 시청자 원문 없음 |
| 운영자 로컬 설정 | configs/app.yaml, 장치·자산 경로 | Git 제외, 예시로 덮어쓰지 않음, 업데이트 때 직접 병합 |
| 런타임 | OAuth/VTS 토큰, 기억 DB·삭제 원장·백업, WAV·자막·로그·프로세스 기록 | 접근 제한된 로컬 저장소, 별도 보관·삭제 절차 |

YouTube OAuth 토큰은 OS 자격 증명 저장소를 사용하고 YAML·명령행·로그에 넣지 않는다.
VTS 토큰 경로와 수동 개발 토큰의 취급은 각 인증 문서를 따른다. `.gitignore`는 접근 제어나 암호화가 아니다.
동기화 폴더·클라우드 휴지통·외부 백업은 별도 사본이므로 Git 제외만으로 안전한 보관이 되지 않는다.

기억은 기본 비활성이고, 허용한 로컬 정보만 저장한다. 로컬 검증 데이터 기본 보관은 1일, 최대 30일이며
조회·쓰기 시 만료를 적용한다. 앱을 끈 동안 예약 삭제 작업이 실행되는 것은 아니므로 필요하면 관리자가
저장 CLI의 purge를 실행한다. YouTube 원문·파생 요약의 장기 저장은 계속 금지다.

`/forget`은 RAM, `/forget-long`은 연결된 로컬 별칭의 원문·사실·요약과 RAM을 삭제한다.
별도 검색 인덱스는 없다. 삭제 원장은 본문 없는 사용자 별칭 해시와 삭제 시각을 남겨 복원 후 부활을 방지한다.
삭제 원장의 자동 만료는 제공하지 않는다. 최신 원장을 보존하는 정책이 백업 복원과 함께 필요하다.
이용자 요청은 운영자가 마련한 실제 연락 경로로 받고 소유자 확인 뒤 처리하며 원문을 다시 복제하지 않는다.

기억 삭제가 기존 백업 파일을 물리적으로 지우지는 않는다. 수동 백업과 자동 pre-migration 백업,
복제본·동기화 휴지통까지 운영자가 목록화하고 폐기 결과를 기록한다. 보관 기간은 배포 운영자가
정해야 하며, 검토되지 않은 실제 데이터의 무기한 수집·보관을 시작하지 않는다.

앱 생성 WAV와 마이크 임시 파일은 정상·실패·취소 정리 경로에서 삭제한다. 강제 종료·전원 중단 때는
잔여 파일이 있을 수 있다. 독립 TTS/녹음 CLI의 명시적 산출물은 자동 삭제하지 않는다.
자막은 검사된 final만 사용하고 중지·정상 종료 시 비우며, 실패한 파일 쓰기를 성공으로 간주하지 않는다.
일반 관측 로그는 응답 ID·시간·상태·폐기 사유를 사용한다. 수용 시험 상세 로그와 파일 변환 CLI 출력도
운영자 전용으로 보관하고 검토 없이 공개 CI 아티팩트로 올리지 않는다.

실제 YouTube 데이터의 허용 범위·삭제 의무는 [인증](youtube-auth.md), [기억](memory.md)의 공식 정책
참조를 따라 별도로 검토한다. 이 문서는 기존 미준비된 방송 데이터 수집을 승인하지 않는다.
